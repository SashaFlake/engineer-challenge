# ADR-004: Стратегия Rate Limiting

**Статус:** Принято  
**Дата:** 2026-04-05  
**Контекст:** Engineer Challenge — модуль аутентификации, деплой в Kubernetes

---

## Решение

**Два слоя rate limiting:**

1. **Nginx** — грубый edge-лимит по IP, защита от флуда. Реализован.
2. **Dragonfly** — точные лимиты по email/операции на уровне приложения, защита от брутфорса. Запланирован.

Слои независимы: Nginx не мешает реализовать Dragonfly-лимиты позже.

---

## Контекст и постановка проблемы

Auth-сервис публично доступен. Единственный публичный эндпоинт `/graphql` уязвим к:
- **DDoS / флуд** — множество запросов с целью перегрузки JVM
- **Брутфорс паролей** — перебор пароля конкретного аккаунта, в том числе с разных IP
- **Credential stuffing** — массовая проверка утёкших пар

Сервис деплоится в 2+ реплик (HPA в Kubernetes, ADR-003).

---

## Анализ

### Слой 1: Nginx (реализован)

`limit_req_zone` по `$binary_remote_addr`: 20 req/s, burst 10.

| | |
|---|---|
| Защищает от | Флуд / DDoS по IP |
| Не защищает от | Брутфорса с разных IP по одному email |
| Код в приложении | Нет |
| Порт аппа снаружи | Закрыт |
| Скалирование nginx | Счётчики не шарятся между репликами |
| Доп. компонент | Да |

### Слой 2: Dragonfly (запланирован)

`INCR rate:{op}:{email}` + `EXPIRE` на уровне приложения.

| | |
|---|---|
| Защищает от | Брутфорса по email с любых IP |
| Корректность при scaling | Да, счётчики шарятся между всеми репликами |
| Доп. компонент | Нет (Dragonfly уже в стеке) |
| Код в приложении | Да |

---

## Почему два слоя, а не один

Каждый слой закрывает уязвимость, которую другой не может закрыть. Nginx не знает про email — он видит только IP. Dragonfly не защищает от флуда — запрос уже дошёл до JVM прежде чем проверка. Два слоя вместе дают полную защиту без избыточной сложности.

---

## Почему Nginx реализован первым

Dragonfly-лимиты требуют реализации в приложении: дизайн, тестирование, единый стандарт обработки ошибок. Nginx даёт edge-защиту немедленно и без кода — это разумный первый шаг, пока Dragonfly-слой готовится.

---

## Последствия

- Nginx добавлен в `docker-compose.yaml` и Helm (`values-prod.yaml`): `limit-rps: 20`, `limit-burst-multiplier: 5`
- Порт приложения не открыт наружу, весь внешний трафик идёт через nginx
- Схема ключей Dragonfly для будущей реализации:

| Ключ | TTL | Лимит |
|---|---|---|
| `rl:login:{email}` | 15 мин | 5 попыток |
| `rl:register:{ip}` | 1 час | 10 регистраций |
| `rl:reset:{email}` | 1 час | 3 запроса |
