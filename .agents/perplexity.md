# .agents/perplexity — Perplexity AI

## Роль в процессе

Perplexity AI (модель Claude Sonnet 4.6 через MCP-интеграцию) использовался как **engineering assistant** — помогал формулировать, структурировать и оформлять, но не принимал архитектурных решений.

**Ключевое разграничение:** всё, что выходило из агента, проходило жёсткую модерацию и ревью разработчиком. Ни одно решение не принималось «as-is».

## Что делал агент

### Написание кода
Агент помогал с бойлерплейтом и scaffold-кодом: структура классов, шаблоны тестов, Gradle-конфигурация. Каждый предложенный фрагмент проверялся и редактировался вручную — часть отклонялась полностью, часть переписывалась.

### Оформление ADR
Агент участвовал в написании ADR, предлагая структуру секций (Context / Decision / Consequences) и формулировки. **Пример:** ADR-001 (Выбор стека и платформы) — агент предложил первый черновик с аргументами за Kotlin vs Go vs JVM-Java. Черновик был существенно переработан: удалены поверхностные аргументы, добавлены реальные trade-offs (coroutines vs virtual threads, value classes для DDD), скорректирован раздел Consequences.

Аналогично для ADR-002 (GraphQL vs REST vs gRPC): агент перечислил стандартные аргументы, разработчик заменил часть из них на специфичные для домена (auth-as-internal-service, introspection как инструмент onboarding).

### Оформление README
Агент прочитал структуру репозитория через GitHub MCP и составил итоговый README на основе реальных артефактов (docker-compose.yaml, список ADR, директории ops/ и helm/). Не добавлял того, чего нет в репозитории.

## Что НЕ делал агент

- Не выбирал стек, фреймворк, протокол или хранилище — это решения разработчика, задокументированные в ADR
- Не генерировал тесты без последующей проверки корректности сценариев
- Не принимал инфраструктурных решений (Helm-структура, NetworkPolicy, HPA-параметры)

## Инструменты

- GitHub MCP (чтение файлов, создание веток, push)
- Perplexity Search (не использовался для этой задачи)

## Итог

Агент ускорил оформление документации и убрал рутину с бойлерплейтом. Качество результата определялось строгостью ревью разработчика, а не качеством генерации агента.
